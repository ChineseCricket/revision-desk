# Review handoff

Use the project’s existing tracker when one is available. These fields also work in a plain Markdown file.

| Field | What to record |
| --- | --- |
| Scope | Stable task, reviewer and proposal IDs, exact reviewer request, permitted edits, questions left for the author |
| Inputs | Original/current source and page version, evidence files, dependencies |
| Assignment | Writer, allowed paths, lock owner if any, expected output and acceptance check |
| Proposal | Candidate wording or figure, stable item link, current proposal version and event revision |
| Technical review | Checks actually performed, commands or evidence locations, outputs, remaining limitations |
| Author decision | Version-specific decision and event sequence, or pending |
| Implementation | Changed files, location, verified output and reviewer |
| Resume | Open questions, owner, next action, where the next session should start |

When requesting rework, give a concrete discrepancy and a reproducible acceptance check. When the coordinator takes over, keep the writer's handoff and add a separate review record.
